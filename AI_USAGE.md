# AI Usage and Methodology

This project was developed using **Google Antigravity** (powered by Gemini models) following the **Superpowers spec-driven development** methodology.

---

## 1. Tools and Process

- **AI Assistant:** Antigravity AI agent.
- **Workflow Methodology:** Spec-driven development (`AGENTS.md`). Every implementation cycle followed:
  1. Specification analysis against `specs/TASKS.md`, `specs/PROJECT_SPECIFICATION.md`, and `specs/WORKFLOWS.md`.
  2. Implementation planning with explicit file paths, verification commands, and rule mapping.
  3. Execution with focused, incremental commits.
  4. Test-driven development (TDD) writing failing unit/integration tests before production logic.
  5. Verification inside Docker Compose containers (`docker compose run --rm backend-tests`).

## 3. Mistakes Encountered and Resolutions

During development, several edge cases, framework changes, and test issues were encountered and resolved:

1. **Solution File Format (`.slnx` vs `.sln`):**
   - *Problem:* Initial dotnet tooling generated an XML-based `.slnx` solution file, which was incompatible with certain standard Docker build tools expecting classic `.sln` format.
   - *Fix:* Recreated the solution using `dotnet new sln --format sln` as `SchoolAdmissionSystem.sln` and bound all project files to it.

2. **Serilog Framework Request Log Duplication:**
   - *Problem:* Serilog emitted both our custom formatted single-line request logs and default ASP.NET Core framework diagnostic request log lines.
   - *Fix:* Added a minimum logging level override for `Microsoft.AspNetCore` (`LogEventLevel.Warning`) in the API host builder so each HTTP request produces exactly one concise log line.

3. **Ambient Environment Variable Pollution in Docker Test Runner:**
   - *Problem:* In Docker Compose, the `backend-tests` container has `ConnectionStrings__Default` set in its container environment. A unit test checking that a missing connection string throws `InvalidOperationException` was picking up this ambient container variable and failing.
   - *Fix:* Updated the test fixture to temporarily clear `ConnectionStrings__Default` and `DATABASE_URL` from the process environment within a `try ... finally` block, restoring them afterward.

4. **React 19 Typing and Build Artifacts:**
   - *Problem:* In React 19.3.1 with strict TypeScript 5.9, subtle type inference differences occurred with JSX component returns and value-only vs. type-only imports.
   - *Fix:* Standardized on `import type` across all React components and hooks, ensuring zero-warning TypeScript compilation under `tsc --noEmit`.

5. **Client-Server Clock Skew in Hold Countdown:**
   - *Problem:* If the client machine clock is skewed relative to the PostgreSQL/backend server clock, a 10-minute hold could visually appear already expired or display inaccurate countdown numbers.
   - *Fix:* Updated the API client (`frontend/src/api/client.ts`) to capture the HTTP response `Date` header via `getLastServerDate()`. The `useCountdown` hook calculates the client-server offset and applies it to `Date.now()`, ensuring millimeter-accurate countdown synchronization.

6. **Storage Access Failures in Restricted Browser Environments:**
   - *Problem:* In private/incognito browsing or browsers with disabled local storage, calls to `localStorage.setItem` can throw `DOMException`.
   - *Fix:* Wrapped student identity and role storage operations in defensive try/catch blocks with in-memory fallbacks, preventing unhandled exceptions and blank pages.
